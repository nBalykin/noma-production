# NOMA Production — сайт-портфолио

TL;DR для Claude: одностраничный сайт-портфолио музыкальной продакшн-студии. Читай этот файл вместо того, чтобы заново прояснять контекст.

## Поддержание этого файла в актуальном состоянии

Этот файл должен отражать текущее состояние проекта, а не историю. Если в ходе работы выясняется что-то, что противоречит написанному ниже (изменился факт, дизайн-решение, договорённость с клиентом, сам код стал вести себя иначе) — **обнови соответствующий раздел сразу, в рамках той же правки**, не дожидаясь отдельной просьбы. Не оставляй файл рассинхронизированным с реальным `index.html`.

В HTML встроены только сжатые копии (base64, см. блок «Награды» в разделе «Механики на странице» ниже), оригиналы отсюда не трогаются — источник при пересжатии/добавлении новых наград. В `.gitignore` (та же логика, что у `Pictures/`/фото команды — уже встроено в HTML, оригиналы не коммитим).

## Стек и почему так

- Чистый HTML/CSS/JS, без React/сборщиков — сознательный выбор для лёгкого хостинга (GitHub Pages и т.п.) и чтобы клиент сам мог редактировать текст.
- Один файл, все стили инлайн + один `<style>` блок сверху с CSS-переменными и media query.
- Референс, который клиенту НЕ нравится: milkmusic.ru (светлый, «самодельный» вид, зелёные кнопки) — сайт сделан подчёркнуто иначе: тёмный, строгий, официальный.
- **Полноценная структура `<!DOCTYPE html><html lang="ru"><head>...</head><body>...</body></html>` — добавлена 2026-09-12.** До этого файл начинался сразу с `<meta charset>` без doctype/`<html>`/`<body>` — браузер доигрывал недостающие теги сам, но в устаревшем Quirks Mode (`document.compatMode === "BackCompat"`, проверено). На обрезку заголовка (см. бага h1 выше) это не влияло — проверено отдельно, тот же баг воспроизводился и со standards-mode doctype. Добавили ради `lang="ru"` (скринридеры и поисковики должны знать язык страницы) и общей корректности. В `<head>` заодно добавлены `<meta name="description">` и Open Graph-теги (`og:type`/`og:title`/`og:description`) — без них ссылка на сайт в Telegram/VK разворачивалась пустым превью. `og:image` не добавлен — нет стабильного захостенного URL для картинки (домен ещё не выбран, base64/data: URI для og:image мессенджеры не читают надёжно); добавить, когда появится домен и/или отдельно захостенный логотип.

## Дизайн-система

- **`.eyebrow` (мелкий цветной лейбл-подпись над `h2`, напр. «КОНТАКТЫ») — НЕ универсальный паттерн секции, клиент убрал его руками из большинства блоков.** Живой (не `hidden`) `.eyebrow` остался только в `#contacts` («Контакты» над «Обсудим ваш трек»). У `#team` («Наша команда»), `#portfolio` («Наши работы»), `#pricing` («Ориентиры по стоимости») и теперь `#awards` («Награды и достижения») — просто голый `h2` без эйбрау, обычный белый цвет (наследуется от `.root { color: var(--text) }`, ничего специально задавать не нужно). У скрытого `#reviews` (`hidden`, см. ниже) эйбрау «Отзывы» ещё остался в разметке — не показатель актуального паттерна, т.к. секция не рендерится живьём. **Если добавляешь новую секцию/подсекцию с заголовком — по умолчанию НЕ добавляй `.eyebrow`**, бери за образец `#portfolio`/`#pricing` (голый `h2`), а не `#contacts`. (История: `#awards` при первом добавлении 2026-09-17 ошибочно скопировал паттерн `#contacts`/`#reviews` с эйбрау — клиент почистил руками, объединив в один белый `h2` «Награды и достижения»; это и вскрыло, что общий переход большинства секций на «просто `h2`» раньше нигде не был зафиксирован в этом файле.)
- Тёмная палитра, CSS-переменные в `:root`: `--bg:#0d0b12`, `--bg-elevated:#17141f`, текстовые `--text/--text-secondary/--text-tertiary/--text-quiet/--text-faint`.
  **Контраст `--text-quiet` и `--text-faint` поднят 2026-09-12** (аудит показал `--text-quiet` 4.36:1 и `--text-faint` 2.55:1 на `--bg` — ниже порога WCAG AA 4.5:1 для обычного текста; использовались для подписи «Артист · (год)» под треками и копирайта в футере). Значения осветлены до `--text-quiet:#8d87a3` (5.71:1) и `--text-faint:#827c9a` (4.94:1) — тот же оттенок, просто светлее; визуально почти незаметная разница, для доступности существенная. `--text-quiet` также используется как дефолтный `--seek-color` шкалы перемотки — от осветления шкала стала чуть заметнее, это не мешает.
- **Акцент: сложный синий `--accent:#4C63D2`** (раньше был салатовый `#b8ff3d` — клиент попросил заменить: слишком «кислотно» на чёрном фоне для премиального/строгого позиционирования под топ-артистов и лейблы). Везде используется только через переменные (`--accent`, `--accent-dim`, `--accent-soft`, `--accent-soft-2`, `--accent-bar`, `--accent-play`, `--on-accent`) — при повторной смене акцентного цвета достаточно поменять блок переменных в `:root`, руками по файлу искать не нужно. `--accent-play: rgba(76,99,210,0.65)` — добавлена 2026-09-12 по просьбе клиента сделать кружки-плеи на обложках треков и бейдж «Авторское» более прозрачными (раньше оба были на сплошном `var(--accent)`); используется в `.track-cover-play` и `.author-badge`, но НЕ в бейдже «Основная услуга» в `#pricing` — его непрозрачность не трогали, не путать эти два визуально похожих бейджа. `--on-accent` — светлый (`#f5f3f9`), т.к. этот синий средней светлоты и белый текст/иконки на нём читаются лучше тёмных.
  **`--accent-text:#8098E8` (добавлена 2026-09-12)** — отдельная, более светлая версия акцента ТОЛЬКО для текста мелким кеглем на `--bg` (сейчас — `.eyebrow`, напр. лейбл «Контакты»): сам `var(--accent)` даёт там всего 3.75:1 (ниже AA), а этот вариант — 7.05:1. Специально не трогали основной `--accent`, чтобы не менять цвет кнопок/иконок/рамок — если нужен текст акцентным цветом мелким шрифтом где-то ещё, бери `--accent-text`, а не `--accent`.
- **Тёплые градиенты `--warm-1:#9a5a2e` / `--warm-2:#3c1f16`** — глубокое амбер/медное свечение на фоне hero (радиальный градиент за заголовком), задаёт «премиальную» глубину в паре с холодным синим акцентом. Если добавляешь новые фоновые свечения/блобы в других секциях — используй эту же пару для консистентности, а не произвольный цвет.
- Шрифты: **Unbounded** (заголовки) + **Manrope** (текст) — оба с кириллицей, из Google Fonts.
- **Главный `h1` в hero — `font-weight: 600`** (SemiBold), не 700/800: клиент просил снизить насыщенность шрифта в заголовке, Ultra-Bold/Bold в Unbounded на таком размере выглядел слишком тяжело. Остальные заголовки (`h2`) остаются на 700 — трогать их не просили.
  **Баг с обрезкой заголовка на узких телефонах (найден аудитом и исправлен 2026-09-12):** на ширинах 320–390px слово «композиторским» (а на совсем узких, ≤340px, ещё и «Музыкальный») не помещалось в отведённую ширину и молча обрезалось справа — `overflow-x: hidden` на `.root` прятал обрезку вместо скролла. Причина не в `text-wrap: balance` (проверено: с обычным переносом и даже со `<!DOCTYPE html>` — та же обрезка) — само слово при фиксированных 32px шире контейнера на большей части мобильного диапазона (напр. ~355px против ~331px на 375px-экране), а обычный перенос никогда не переносит середину слова.
  Первая версия фикса (`overflow-wrap: break-word`) убирала обрезку, но ценой некрасивого переноса СЕРЕДИНЫ слова без дефиса — и не только на редких ≤340px, а и на самых массовых ширинах 375/390px (iPhone SE/mini/12–14), это заметили и пересмотрели в той же сессии. **Итоговый фикс — плавающий `font-size` вместо фиксированного 32px:** `h1 { font-size: clamp(24px, -8px + 10vw, 32px) !important; overflow-wrap: break-word !important; hyphens: auto !important; }`. Формула линейно уменьшает кегль с 32px (при ≥412px, где слово и так помещается) до 24px (при ≤320px, где рассчитано, что слово влезает без переноса) — подобрано так, чтобы «композиторским» помещалось целиком на любой ширине 320–860px без разрыва посреди слова (проверено визуально на 320/375/390px — переносы только между словами). `overflow-wrap: break-word` оставлен как страховка на случай экрана уже 320px (там `clamp` не даст кеглю упасть ниже 24px, и на очень редких/старых устройствах <~310px разрыв середины слова теоретически возможен). `hyphens: auto` эффекта не дал (нет словаря переносов для русского в тестовом Chromium) — оставлен как бесплатное прогрессивное улучшение. **Если будешь трогать текст заголовка** — формула `clamp` подобрана под длину конкретного слова «композиторским»; при другом, более длинном тексте пересчитай коэффициенты (см. историю сессии — считалось через `canvas.measureText` на реальном шрифте, не на глаз).
- Стиль сознательно «строгий/официальный»: прямоугольные скругления по 6–12px (НЕ pill-кнопки), никаких ховеров с движением/подпрыгиванием (только смена цвета/яркости), минимум анимации.
- **Логотип в шапке — растровый PNG (base64), не инлайн-SVG.** `.brand-logo` — это `<a href="#top">` с одним `<img>` внутри (монограмма N + акустическая волна + текст «NOMA PRODUCTION» на прозрачном фоне, цвет шампань-золото уже запечён в самом PNG). Классов `.logo-stroke`/`.logo-text` и переменных `--logo-gold`/`--logo-gold-hover` в разметке больше нет как активно используемых — эти CSS-переменные остались объявлены в `:root`, но логотип их не читает (цвет зашит в пиксели картинки), трогать их бессмысленно, если меняешь цвет лого — нужно перегенерировать сам PNG. Если нужен только значок-монограмма отдельно от текста (напр. для фавикона) — обрежь этот же PNG по левой части (см. ниже, как это уже сделано).
  **История бага (закрыт 2026-09-11):** до этой правки в `.brand-logo` реально лежал не `<img>`, а самодельный inline-SVG с вручную набранными `d="..."` путями — CLAUDE.md уже описывал целевой PNG-вариант, но в код это тогда не попало, и SVG-путь рендерился как нечитаемая клякса вместо буквы N (эту рассинхронизацию документации и кода нашли и исправили только сейчас). Клиент прислал готовый референс-скриншот логотипа — фон обрезан по bounding box золотых пикселей и сделан прозрачным через chroma-key (PowerShell/System.Drawing), вставлен как base64 `<img>` вместо SVG. Ссылка вокруг лого была `href="/"` (битая — сайт без роутинга) — заменена на `href="#top"` (`id="top"` на `.root`).
- **Фавикон и `<title>`:** `<title>NOMA Production</title>` + три `<link>` в первых строках файла (до `<style>`) — `rel="icon" sizes="32x32"`, `rel="icon" sizes="16x16"`, `rel="apple-touch-icon" sizes="180x180"`, все с `href="data:image/png;base64,..."` (никаких отдельных файлов вроде `/favicon-32x32.png` — сайт остаётся одним самодостаточным HTML).
  **32×32 и 16×16 — не просто уменьшенная детальная монограмма, а отдельная упрощённая версия.** Прямой ресайз полной монограммы (тонкие двойные линии волны + вертикальные штрихи «N») на 16px превращался в нечитаемое пятно — клиент сам заметил это и прислал референс с более простой/жирной иконкой для маленьких размеров. Сделано так: монограмма обрезается ещё теснее — только центральная часть с буквой N (без тонких хвостов волны слева/справа, которые на квадратной маленькой иконке всё равно превращаются в обрубки), затем бинаризуется (сплошной `--logo-gold` без полутонов) и «утолщается» через штамповку копий со сдвигом по кругу (дешёвая имитация morphological dilate через `Graphics.DrawImageUnscaled` в цикле по смещениям — попиксельный blur/threshold в PowerShell на изображении такого размера считается минутами и один раз реально зависал, поэтому решали через GDI+ трюк, а не ручные циклы по пикселям), пока соседние линии не сольются в жирный сплошной силуэт. 16×16 использует более сильное утолщение (радиус ~7px на кропе), 32×32 — чуть слабее (радиус ~3px), чтобы сохранить немного текстуры волны внутри буквы. **180×180 (apple-touch-icon) — та же обрезка монограммы, что и раньше, БЕЗ упрощения** — на таком размере тонкие линии читаются нормально, упрощённая версия там не нужна и будет смотреться грубее оригинала.
  Если логотип в шапке заменят на новый — все три иконки надо перегенерировать из нового файла: 180px — обычным кропом (bounding box → центрирование → ресайз), 32/16px — через описанный выше пайплайн «обрезать core → бинаризовать → утолщить → обрезать по новому bbox → центрировать → ресайз», а не просто уменьшить детальную версию.
  **Если пришлют «сгенерируй фавикон через favicon.io/realfavicongenerator» с инструкцией по отдельным файлам:** не заводить отдельные PNG/ICO-файлы и не грузить бренд-ассет на сторонний сервис — здесь это не нужно, тот же результат (несколько размеров, apple-touch-icon) получается локально из уже готового логотипа через PowerShell, base64 прямо в HTML.
- **Кнопка `.btn-ghost` («Обсудить проект» и подобные)** — не просто обводка `var(--border-soft)` (она была почти не видна на тёмном фоне и не читалась как кликабельная). Итог: играет всегда ровно один трек синим, все остальные (включая те, что на паузе с прогрессом > 0) — серые. Переход мгновенный, без transition — анимировать `--seek-color` плавно потребовало бы `@property` (кастомные CSS-переменные сами по себе не интерполируются), сочли лишней сложностью ради того, что и так соответствует принципу сайта «минимум анимации».
  **Пауза сохраняет позицию, сбрасывается только по завершении трека (тоже 2026-09-12, по прямой просьбе клиента — раньше пауза сбрасывала прогресс в 0, это и есть основная причина, почему вообще нужен класс `is-active` отдельно от «трек ненулевой»):** `stopCurrent()` только ставит на паузу (`audio.pause()`) и снимает `is-active`/иконку — **не трогает `currentTime` и не обнуляет шкалу**; так что если поставить трек на паузу и потом снова нажать play (или переключиться на другой трек и вернуться), он продолжит с того же места, просто в сером виде, пока не активен. Обнуление (`currentTime = 0` + `resetSeek()`) происходит только по событию `ended` — трек естественно доиграл до конца, значит следующий плей должен начаться заново. Скролл: если добавляешь новый способ остановки трека, различай эти два случая (пауза vs логическое завершение) — не сливай их обратно в одну функцию.
  Скрабом можно тащить/кликать по шкале в любой момент, даже по треку, который сейчас не играет — `input`-хендлер сам активирует нужный трек (переиспользует ту же `activate()`, что и клик по кнопке play), останавливая предыдущий. Т.к. `<audio preload="none">`, у только что нажатого трека `duration` какое-то время `Infinity`/неизвестна — если утащить шкалу до того, как длительность резолвится, процент запоминается в `audio.dataset.pendingSeek` и применяется на `loadedmetadata`/`durationchange`. JS — в конце `<script>`, рядом с `track-cover-play` (`setSeekFill`/`resetSeek`/`stopCurrent`/`activate`/сам `forEach`).
  **Важно (проверено вручную в браузере, не полагайся на теорию):** казалось, что перемотка `.opus`-файлов в Chromium ломается (seek молча сбрасывался в 0) — оказалось, это был артефакт тестирования: повторный `navigate()` на тот же URL (с `#hash` или без) в Browser pane переиспользует старый JS-контекст вместо реальной перезагрузки страницы (проверяется меткой вроде `window.__marker = Math.random()` до/после). На честной свежей загрузке перемотка и вперёд, и назад по `.opus` работает корректно и точно. Если снова возникнет подозрение на баг с перемоткой аудио — сначала исключи именно это (форсируй реальный reload, напр. cache-busting `?t=...` в URL), прежде чем городить обходные пути (напр. переключение на `.mp3`-источник при неудачном seek) — в этом файле такой код уже был написан и удалён как решение несуществующей проблемы.

## Как добавлять/менять фото

Файлы вставляются как `background-image: url('data:image/jpeg;base64,...')` прямо в HTML (сайт — один самодостаточный файл). Т.к. base64 очень длинный, **не вставляй его вручную через Edit** — используй PowerShell:

```powershell
Add-Type -AssemblyName System.Drawing
# ресайз/сжатие в JPEG ~800-900px по стороне, quality ~80-85, если оригинал большой
# затем [Convert]::ToBase64String(bytes) и .Replace() нужного места в файле через
# [System.IO.File]::ReadAllText/WriteAllText с New-Object System.Text.UTF8Encoding($false)
# (важно: без BOM, иначе кириллица может испортиться)
```

Смотри историю правок в этом же чате/сессии как пример точных команд (ресайз фото Дениса, вставка фото Никиты, вставка фото Максима — обычный `cover`, ресайз до 900px, quality 85).

При вставке добавляй `role="img" aria-label="Фото: Имя"` (для фото команды) или `aria-label="Обложка трека «Название»"` (для обложек) на тот же `<div>`, где `background-image` — CSS-фон сам по себе невидим для скринридеров (см. «Обложки и фото команды помечены для скринридеров» выше).

## Хостинг (уже обсуждено с клиентом, решение принято)

Рекомендовано и согласовано: **GitHub Pages** как основной хостинг (бесплатно, статике достаточно), домен покупается отдельно у любого регистратора и направляется DNS-записями. Клиент сказал, что готов немного разобраться с git.

**Аудио — статус изменился.** Изначально была договорённость не хостить аудио/видео самим, а встраивать плееры (Яндекс.Музыка/VK/YouTube). Клиент прислал реальные WAV-мастера треков и попросил подключить прямо на сайте — сейчас превью треков в портфолио играют самостоятельно захостенные Opus/MP3 (см. `Audio/web/` выше), а не внешние плеер-виджеты. Суммарный вес `Audio/web/` — около 63 МБ на 15 треков (сжаты из ~420 МБ WAV), это уже приемлемо для GitHub Pages. Сырые WAV-мастера (`Audio/`) коммитить не нужно — это чистые исходники, не то, что должно попасть в репозиторий/на хостинг. Если клиент решит вернуться к идее внешних плееров вместо самостоятельного хостинга — заменить `<audio>`-блоки на iframe-виджеты, структура портфолио (список треков) от этого не изменится.
